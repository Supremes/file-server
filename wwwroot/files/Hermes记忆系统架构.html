每一层解决不同的记忆问题，从即时上下文到永久知识积累

Layer 1

🧠 工作记忆 — 即时上下文

每次会话开始时注入系统提示词，整个会话期间保持冻结（保证 LLM 缓存命中）

system prompt 注入示例

══════════════════════════════════════════════
MEMORY (your personal notes) [67% — 1,474/2,200 chars]
══════════════════════════════════════════════
VPS: 185.239.224.219 (SSH alias `vps`, port 12761)
§
LeetCode Tracker: Flask + SQLite on VPS, port 8081
§
Market Dashboard: Flask on VPS, port 8082

══════════════════════════════════════════════
USER PROFILE (who the user is) [43% — 593/1,375 chars]
══════════════════════════════════════════════
Communication style: terse, direct. Responds in Chinese.
§
Prefers concise replies — just confirm what was fixed
1

会话启动

从 ~/.hermes/memories/ 加载 memory.md 和 user.md

2

注入系统提示词

渲染为 § 分隔的文本块，附带容量百分比

3

冻结不变

整个会话期间不更新注入内容，保证 prefix cache

4

磁盘即时持久化

memory tool 的修改立即写入文件，下次会话生效

Layer 2

💾 持久记忆 — 跨会话记忆

两个文件，严格容量限制，Agent 自主管理（增/删/改）

📝

MEMORY.md — Agent 笔记

环境事实、项目约定、工具经验、踩坑记录。Agent 自己的"笔记本"。

📁 ~/.hermes/memories/memory.md 📏 2,200 chars (~800 tokens) 📊 8-15 条目
👤

USER.md — 用户画像

用户偏好、沟通风格、技术栈、工作习惯。让 Agent "认识你"。

📁 ~/.hermes/memories/user.md 📏 1,375 chars (~500 tokens) 📊 5-10 条目

memory tool 三种操作

# 添加记忆
memory(action="add", target="memory", content="项目使用 pytest + xdist")

# 替换记忆（子串匹配定位）
memory(action="replace", target="user",
      old_text="concise", content="用户偏好极简回复，不要解释")

# 删除记忆
memory(action="remove", target="memory", old_text="临时路径")

🔒 安全机制

• 注入扫描：所有记忆写入前经过 prompt injection 和 credential exfiltration 模式检测
• Unicode 检查：拦截不可见字符注入
• 去重：自动拒绝完全重复的条目
• 容量硬限：超出时返回错误，Agent 需先整合/清理旧条目

Layer 3

🔍 会话存储 — 全历史检索

SQLite + FTS5 全文搜索，所有对话永久保存，三种检索模式

Discovery

关键词搜索
找到相关会话

→

Scroll

定位到具体消息
±N 窗口展开

→

Browse

最近会话列表
时间线浏览

三种检索模式示例

# 1. Discovery — 关键词发现
session_search(query="leetcode tracker bug fix", limit=3)
# → 返回匹配会话 + FTS5 高亮摘要 + 首尾消息 + 上下文窗口

# 2. Scroll — 定位特定消息
session_search(session_id="abc123", around_message_id=456, window=10)
# → 返回 ±10 条消息的上下文

# 3. Browse — 最近会话
session_search()
# → 按时间倒序返回最近会话列表

⚡ 性能特点

• 零 LLM 开销：纯 SQLite 查询，不消耗 token
• FTS5 全文索引：支持 AND/OR/引号短语/布尔/前缀通配
• 精确引用：返回原始消息文本，不做摘要或截断
• 书签结构：返回会话首尾 3 条消息 + 匹配上下文 ±5 条

Skill 加载流程

# 1. 用户发送消息
# 2. Agent 扫描 available_skills 列表
# 3. 匹配 → 调用 skill_view(name) 加载完整内容
# 4. 按 Skill 指令执行（命令、陷阱、验证）
# 5. 执行完毕 → 用 skill_manage 更新过时内容

skill_view(name="flask-vps-development")
# → 返回 SKILL.md 内容 + 可用附属文件列表

skill_manage(action="patch", name="flask-vps-development",
             old_string="port 8080", new_string="port 8082")

Comparison

五层记忆对比

每一层解决不同粒度的记忆需求

层级 名称 容量 延迟 Token 成本 管理方式 典型用途
L1 工作记忆 ~3000 tokens 0 (预注入) 每轮固定 自动注入 始终在上下文中
L2 持久记忆 3,575 chars ~0 (磁盘读) ~1,300 tokens/会话 Agent 自主 关键事实、用户偏好
L2+ 外部记忆 无限制 ~50-200ms 按需 插件管理 知识图谱、语义搜索
L3 会话存储 无限制 ~20ms FTS5 零 (纯 DB) 自动存储 历史对话检索
L4 技能库 无限制 ~0 (文件读) 按需加载 Agent + 用户 可复用流程、操作手册
L5 上下文文件 项目级 ~0 (自动发现) 注入即消耗 只读 项目规范、开发指南

Philosophy

🎯 设计哲学

为什么这样设计记忆系统？

💰

Token 经济学

L1 工作记忆每轮消耗 token，所以严格限制在 ~3000 tokens。L3 会话存储零 token 开销（纯 DB 查询），按需加载。L4 Skills 只在匹配时加载。

🧊

冻结快照模式

L1 内容会话开始后不变，即使中途修改了 memory.md。这保证了 LLM 的 prefix cache 命中率，显著降低延迟和成本。

🎯

有限 vs 无限

关键事实（L2）用有限容量强制精选。历史记录（L3）无限制但按需检索。结构化知识（L4）独立文件系统。各司其职。

🔒

安全边界

记忆注入系统提示词，是 prompt injection 的高危入口。所有写入经过威胁模式扫描、Unicode 检查、去重验证。外部提供商作为独立层叠加。
